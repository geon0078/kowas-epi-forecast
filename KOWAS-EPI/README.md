# KOWAS-EPI — 하수 감시 데이터 기반 감염병 유행 조기예측

> 2026 DATA·AI 분석 경진대회 문제 **「하수 감시 데이터 기반 감염병 유행 조기예측 AI 모델 개발」** 참가자 안내서
> 데이터 기준: 질병관리청 KOWAS 공식 시·도 주간 통계  · 기상·전국 집계·임상 자료 2026-09-14 수집분

---

## 1. 문제 소개

질병관리청은 2023년 4월부터 하수 기반 감염병 감시체계(KOWAS)를 운영하며, 전국 17개 시·도 하수처리장에서 주 1회 이상 바이러스 농도를 측정합니다. 현재 주간 분석보고는 농도 현황과 전주 대비 증감을 알려 주지만, 앞으로 유행이 얼마나 커질지 정량적으로 예측하지는 않습니다.

이 문제는 **시점 t까지 공개된 정보로 시·도별 2주 뒤(t+2) 하수 바이러스 농도와 급증 경보를 예측**하는 모델을 만드는 것입니다.

> **예측 범위.** 채점 대상은 하수 감시 지표(t+2주 하수 농도와 급증 경보)입니다. 임상 환자 수를 직접 예측하는 과제가 아니며, 문제명의 ‘감염병 유행 조기예측’은 하수 기반 선행 신호를 뜻합니다.

하수 농도·전국 집계·임상 신고수는 공개 통계의 원값이고, 강수·기온은 재분석 추정치입니다. 빈 격자 행(`no_source_row`)·파생 변수(`conc_log10`·`conc_base_avg`)·t+2 라벨은 이 안내서에 적은 규칙으로 만들었으며, 임의로 만든 합성 수치는 없습니다.

## 2. 과제 정의

| 구분 | 내용 |
|---|---|
| 단위 | 시·도(17개) × 주차 |
| 원점 주차 t | 예측을 하는 주. t주까지 공개된 자료만 쓸 수 있습니다 |
| 목표주 t+2 | 맞힐 주 |

### 4-2. 라벨 생성 규칙

```
규칙 ①  conc_base_avg   = 같은 시·도의 t−3 ~ t 4개 주 중 conc_mean 이 있는 값들의 평균
                          (값이 2개 미만이면 공란) — t까지의 정보만 사용
규칙 ②  target_conc_t2  = 같은 시·도의 t+2주 conc_mean (없으면 공란, t+1주 여부는 무관)
규칙 ③  target_alert_t2 = 1 if target_conc_t2 >= 1.3 × conc_base_avg else 0
                          (①·② 중 하나라도 공란이면 공란)
정밀도  모두 이 CSV 의 conc_mean(소수 둘째 자리) 값으로 계산, conc_base_avg 는 넷째 자리로 저장
```

2026-W35·W36 행은 목표주(W37·W38) 자료가 아직 없어 라벨이 공란입니다. 아래 코드로 라벨을 직접 재현할 수 있습니다.

```python
import csv
rows = list(csv.DictReader(open("kowas_epi_panel.csv", encoding="utf-8")))
by = {(r["region_code"], r["date_week"]): r for r in rows}
weeks = sorted({r["date_week"] for r in rows})             # 빈 주가 없으므로 순번 = 달력 주차
idx = {w: i for i, w in enumerate(weeks)}
bad = 0
for r in rows:
    i, code = idx[r["date_week"]], r["region_code"]
    obs = [float(by[(code, weeks[j])]["conc_mean"]) for j in range(max(i - 3, 0), i + 1) if by[(code, weeks[j])]["conc_mean"]]
    base = sum(obs) / len(obs) if len(obs) >= 2 else None
    t = by.get((code, r["target_week_t2"]))
    tgt = float(t["conc_mean"]) if t and t["conc_mean"] else None
    alert = None if base is None or tgt is None else int(tgt >= 1.3 * base)
    bad += (base is None) != (r["conc_base_avg"] == "") or (base is not None and abs(base - float(r["conc_base_avg"])) > 5e-5)
    bad += (tgt is None) != (r["target_conc_t2"] == "") or (alert is not None and alert != int(r["target_alert_t2"]))
print("불일치", bad)   # 기대 출력: 불일치 0
```

### 4-3. `conc_3wk_avg`는 `conc_mean`의 이동평균이 아닙니다

KOWAS가 처리장·시료 단위 원자료로 산출해 제공하는 3주 평균 지표를 그대로 옮긴 값입니다. `conc_mean`을 3주 이동평균해도 같은 값이 나오지 않고, `conc_mean`이 없는 주에도 값이 있을 수 있습니다. **독립 입력 변수**로 다루십시오. 평가의 기준선은 이 열을 그대로 예측값으로 씁니다(§8).

### 4-4. 주차

주차는 KOWAS·질병관리청과 같이 **일요일에 시작해 토요일에 끝나는 주**입니다. 번호는 `YYYY-Www` 형식으로 적지만 **ISO 8601 주차(월~일)와 같지 않습니다**. KOWAS 주차 번호는 그 주 월요일의 ISO 주차 번호와 같아서 월~토 날짜는 ISO 주차와 일치하고, 일요일 날짜는 ISO상 한 주 앞 번호가 됩니다(예: 2023-W14의 시작일 2023-04-02는 ISO 2023-W13). 외부 자료는 주차 번호가 아니라 **날짜(`week_start_date` ~ +6일)** 기준으로 결합하십시오. `week_start_date`가 그 주의 일요일입니다. 기상 변수도 이 7일로 합계·평균했습니다.

| 연말 미보고 (공식 통계 없음) | 2023-W52 · 2024-W52 · 2025-W52 | 51 | `no_source_row` |
| 연초 부분 보고 | 2025-W01 (2개 시·도만 측정) | 15 | `no_source_row` 14 · `no_measurement` 1 |
| 측정 없는 레코드 | 2026-W01 (1개 시·도만 측정) | 16 | `no_measurement` |
| 일부 시·도 미측정 | 그 외 56개 주 (측정 시·도 5~16개, 2023-W43·W44는 5개) | 114 | `no_measurement` |
| **합계** | 179주 중 118주는 17개 시·도 모두 측정 | **196** | |

`conc_mean` 결측 196행은 `n_sites = 0`과 정확히 일치합니다. 결측값은 채워 두지 않았습니다.

### 5-2. 스케일 차이
분석 프로토콜 차이로 시·도 간 농도가 100배 이상 차이 나고, 연도별로도 수준이 크게 다릅니다. `conc_mean` 중앙값은 2023년 55,555 → 2024년 8,520 → 2025년 5,350 → 2026년 1,359이며, 최댓값은 2023년 50,824,298, 2026년 102,296입니다. 시·도별·기간별 정규화나 로그 변환이 사실상 필요합니다.

### 5-3. 극단 증감률
`wow_change_rate`는 KOWAS 제공값을 그대로 옮겨 −4,731 ~ 9,639 범위의 이상치가 있습니다. 필요하면 `conc_mean`으로 증감률을 직접 계산해 쓰십시오.

### 5-4. 핵심 난제 — 시·도 집계에서는 강수 희석 효과가 보이지 않습니다

비가 많이 오면 하수가 희석되어 농도가 낮아질 것으로 예상되지만, 시·도 주간 집계에서는 그 효과가 거의 드러나지 않습니다. 농도·3주 평균값이 양수이고 기상이 있는 2,847행으로 검정했습니다.

| 검정 | 명세 | 결과 |
|---|---|---|
| A. 강수 희석 부분상관 | 종속 `log10(conc_mean / conc_3wk_avg)`, 설명 `log(1 + precip_mm)`, 통제 시·도 더미 + `sin/cos(2π·주차/52)`, 통제변수에 대한 잔차끼리 피어슨 상관 | r = −0.007 (강수 원 단위면 −0.004) |
| B. 기상의 추가 설명력 | 종속 `conc_log10`, 기저 시·도 더미 + 계절항 + `log10(1 + conc_3wk_avg)`, 추가 `log(1 + precip_mm)`·`temp_avg` | ΔR² = +0.0002 |

한 시·도 안에 여러 유역이 섞여 신호가 상쇄되는 것으로 봅니다. **처리장을 집수지역에 매핑해 유역 단위 강수를 결합하면 예측이 좋아지는지**는 아직 검증되지 않은 가설이며, 이 문제의 핵심 도전 과제입니다(§7).

### 5-5. 측정 처리장 변동
`n_sites`가 주마다 0~12로 바뀌고, 채취 처리장이 바뀌면 `pop_sampled`도 달라집니다. 가중치나 신뢰도 보정에 쓸 수 있습니다.

`pop_sampled`는 KOWAS가 제공한 채취 처리장 처리인구를 그대로 옮긴 값이며 **중복 없는 서비스 인구가 아닙니다**. 201행(서울 110 · 대전 91, 6.6%)에서 `pop_served`보다 크고 최대 2.02배입니다. 서울 11,268,168명은 현행 5개소 합 9,667,667명에 과거 처리장 중랑B(P071) 1,600,501명이 더해진 값이고(2023-W40~2025-W51), 대전은 같은 처리인구가 기재된 P019·P065가 함께 더해진 주가 있습니다(최대 2,913,348명). `pop_sampled / pop_served`를 감시 커버리지 비율로 해석하지 마십시오.

### 5-6. 데이터 규모
행은 3,043개지만 독립 시계열은 17개 시·도 × 179주이고, 결측과 프로토콜에 따른 수준 변동이 큽니다. 대규모 딥러닝이나 GNN이 반드시 유리하지 않고 과적합되기 쉽습니다. 통계 시계열·트리·베이지안·GNN 등 방법은 자유이며, 기준 모델을 여러 평가 창에서 고르게 이기는지(시간 외삽 성능)가 중요합니다.

## 6. 하수와 임상 지표의 연관

회귀 채점 행은 라벨이 있고 원점 주차 `conc_3wk_avg`도 있는 행입니다. 기준선을 계산할 수 없는 69행은 회귀 채점에서 빠지므로 회귀와 분류의 채점 행은 서로 다를 수 있습니다.

각 평가 창에서 `evaluation.py`는 다음 순서로 모델을 실행합니다.

1. `Model()`을 새로 만들고 `fit(rows, national)`을 한 번 호출합니다. 넘기는 자료는 **목표주 시작 2주 전(학습 자료 기준 주)까지** 공개된 패널·전국 집계입니다.
2. 목표주를 한 주씩 옮기며 원점 t = 목표주 − 2마다 `predict(rows, t, national)`을 호출합니다. 넘기는 자료는 **t주까지** 공개된 행입니다.
3. 두 경우 모두 기준 주 이후 행은 빠져 있고, 기준 주 이후가 목표주인 라벨은 빈 값으로 가려져 있습니다.

### 8-2. 지표

```
평가 창 점수   = 0.6 × (1 − sMAPE / sMAPE_기준선) + 0.4 × Macro-F1
sMAPE          = (100 / n) × Σ 2·|ŷ − y| / (|y| + |ŷ|)          (분모 0인 항은 0)
Macro-F1       = 경보 0·1 각각의 F1 평균 (한 클래스가 실제·예측 모두 0건이면 그 클래스 F1 = 1)
sMAPE_기준선   = 같은 행에서 ŷ = 원점 주차의 conc_3wk_avg 로 계산한 sMAPE
                 (conc_3wk_avg 가 없는 행은 모델·기준선 양쪽에서 제외)
최종 정량점수  = 평가 창 10개 점수의 단순 평균
```

- 회귀는 라벨 `target_conc_t2`가 있는 행, 분류는 `target_alert_t2`가 있는 행만 채점합니다.
- 기준선보다 sMAPE가 나쁘면 회귀 항이 음수가 됩니다. 창 점수의 최댓값은 1(sMAPE 0, Macro-F1 1)이고 하한은 없습니다. 예) 기준선 sMAPE 60%인 창에서 sMAPE 48%·Macro-F1 0.65면 0.6 × 0.2 + 0.4 × 0.65 = 0.38.
- 평가 창 점수는 창의 행 수(160~221행, 10주짜리 2026-Q3 포함)와 관계없이 **같은 비중**으로 평균합니다. 행이 많은 시기에 치우치지 않고 기간마다 고르게 맞히는 모델을 우대하려는 선택입니다.
- 채점은 이 배포본의 값으로만 하며, 이후 원천 자료가 정정되어도 반영하지 않습니다.

### 8-3. 기준 모델 성능 (`baseline_model.py`)

회귀 = KOWAS 제공 3주 평균값, 분류 = 현재 경보 지속 규칙(`conc_mean`(t) ≥ 1.3 × `conc_base_avg`(t))

|---|---|---|---|
| 2024-Q2 | 67.60% | 0.4935 | 0.1974 |
| 2024-Q3 | 90.86% | 0.6611 | 0.2645 |
| 2024-Q4 | 72.76% | 0.5363 | 0.2145 |
| 2025-Q1 | 54.74% | 0.5183 | 0.2073 |

| 2025-Q3 | 52.62% | 0.5682 | 0.2273 |

### 9-2. `Model` 인터페이스

```python
class Model:
    def fit(self, rows, national):
        """rows: 패널 행(dict, 값은 문자열) · national: 전국 집계 행. 학습 자료 기준 주까지 공개된 자료."""

    def predict(self, rows, origin_week, national):
        """origin_week 까지 공개된 자료로 목표주(origin_week + 2)를 예측.
        반환: {region: (pred_conc, pred_alert)} — 17개 시·도 모두, pred_conc 는 0 이상 실수, pred_alert 는 0 또는 1"""
```

- `rows`의 값은 모두 문자열이고 결측은 빈 문자열입니다.
- `predict` 안에서 추가 학습을 해도 됩니다(최근 자료로 모델 갱신 등). 넘겨받은 자료 밖의 패널·전국 집계 파일은 읽지 마십시오.
- Python 외 언어는 `Model` 안에서 외부 프로그램을 호출하는 방식으로 감쌀 수 있습니다.

| 실행 실패 | 환경 문제(패키지·경로)로 실행되지 않으면 모델을 바꾸지 않는 조건으로 1회 수정 재제출할 수 있습니다. 코드 오류·예측값 형식 오류가 난 평가 창은 **가능한 최저 점수**(sMAPE 200%, Macro-F1 0으로 계산한 창 점수)로 처리하고 나머지 창은 계속 채점합니다(`--keep-going`). 팀당 전체 실행 시간 상한(§9-1)을 넘기면 1회 재실행하며, 재실행에서도 상한 안에 끝나지 않은 평가 창만 최저 점수로 처리합니다 |
| 코드 검토 | 제출 코드가 §9-1 규칙을 지키는지 검토합니다 |

**제출 전 점검 권장** — 새 가상환경에 의존성 목록만 설치하고 네트워크를 끊은 상태에서 `python evaluation.py backtest --model model.py`가 끝까지 실행되는지 확인하십시오. 대회 중 운영측 사전 실행 점검은 제공하지 않습니다.

## 12. 자주 묻는 질문

**리더보드가 있나요?**
없습니다. 정답이 배포본에 들어 있어 `evaluation.py`로 계산한 점수가 운영측 채점 방식과 같습니다. 정량 순위는 운영측이 제출 코드를 다시 실행한 점수로 정하고, 최종 수상은 발표평가로 결정합니다(§8-4).

**원천 사이트에서 최신 자료를 받아 써도 되나요?**
분석·탐색에는 자유롭게 쓸 수 있습니다. 다만 채점은 이 배포본으로 하고, 제출 코드는 `evaluation.py`가 넘겨주는 자료만으로 동작해야 합니다.

**엑셀에서 CSV를 열면 한글이 깨집니다.**
CSV는 UTF-8(BOM 없음)입니다. 엑셀의 ‘데이터 → 텍스트/CSV에서 가져오기’로 UTF-8을 지정해 여십시오. pandas는 `pd.read_csv(파일, encoding="utf-8")`로 읽으면 됩니다.

**모델이 넘겨받은 `rows`를 고쳐도 되나요?**
네. 평가 코드는 매번 사본을 넘기므로 원본 자료나 채점에 영향이 없습니다.

**결측 주는 어떻게 다루나요?**
채우는 방법은 자유입니다. 라벨이 없는 행은 채점하지 않으므로 그 주의 예측값은 점수에 영향이 없지만, 형식상 모든 키에 예측값이 있어야 합니다.

**`conc_base_avg`를 입력으로 써도 되나요?**
네. 원점 t까지의 값만으로 계산되므로 미래 정보가 없습니다.

**평가 창이 공개되어 있는데 창에 맞춰 조정해도 되나요?**
10개 창 전체에서 고르게 잘 맞는 모델을 고르는 교차검증은 정상적인 방법입니다. 다만 특정 주차·연도를 가리키는 조건문이나 값 표로 성능을 올리는 것은 §9-1 위반입니다.
